1. Especificación Formal de la Gramática

El lenguaje MiniWebLang está definido por una Gramática Independiente del Contexto (GIC) de tipo 2, lo que permite el uso de un Autómata de Pila para su reconocimiento.

Notación EBNF (Extended Backus-Naur Form)

Gramática Formal
<programa>      ::= <instruccion>*
<instruccion>   ::= <lineal> | <bloque> | <especial> | <lista_item>
<lineal>        ::= ("TITULO" | "ENCABEZADO" | "PARRAFO" | "BOTON") CADENA ";"
<bloque>        ::= ("SECCION" | "LISTA") [ "{" ] <programa> [ "}" ] ";"
<especial>      ::= ("ENLACE" | "IMAGEN") CADENA CADENA ";"
<lista_item>    ::= "ELEMENTO" CADENA ";" | "SUBLISTA" [ "{" ] <programa> [ "}" ] ";"
<cadena>        ::= "\"" (Caracter)* "\""

2. Análisis Léxico (Autómata Finito)

El Lexer utiliza una Matriz de Transición Determinista. No se utilizan sentencias if/else para la lógica de estados, lo que garantiza un rendimiento constante e independiente de la complejidad del token.

Matriz de Transiciones Expandida

Estado Actual Letra [A-Z] Dígito [0-9] Comilla ["] PuntoComa [;] Slash [/] Acción Resultante
Q0 (Inicio) Q1 Error Q2 Q7 Q4 Búsqueda de nuevo Lexema
Q1 (Comando) Q1 Q1 Aceptar Aceptar Aceptar Reconocimiento de Palabra Reservada
Q2 (Cadena) Q2 Q2 Q3 Q2 Q2 Captura de texto literal
Q4 (Comentario) Error Error Error Error Q5 Entrada a modo ignorar

3. Análisis Sintáctico (PDA - Autómata de Pila)

El Parser gestiona la jerarquía del documento mediante una pila (Stack) que asegura que etiquetas como <ul> o <section> se cierren en el orden inverso al que se abrieron (LIFO).

Control de la Pila (Simulación)

Entrada (Token) Operación Pila Estado Pila Salida HTML
SECCION PUSH("section") [#, section] <section>
LISTA PUSH("ul") [#, section, ul] <ul>
; (Cierre Lista) POP() [#, section] </ul>
; (Cierre Seccion) POP() [#] </section>

4.2 Pila de Errores con Recuperación

El sistema implementa Panic Mode Recovery: cuando se encuentra un error, el parser busca el siguiente delimitador ; para intentar retomar el análisis sin abortar el programa completo.

5. Categorización de Errores y Casos de Prueba

Código
Categoría
Descripción Técnica
L001
Léxico
Caracter fuera del alfabeto Σ = {A-Z, 0-9, ", ;, /, {, }}.
P001
Sintáctico
Falla en la transición de la matriz de estados del PDA.
S001
Semántico
Tope de pila inválido para el comando solicitado (Contexto).
C001
Comando
Lexema reconocido como comando pero no definido en el diccionario.

Ejemplos de Falla y Respuesta

// Entrada Errónea
ELEMENTO "Hola"; // S001: ELEMENTO fuera de LISTA
$variable;       // L001: Caracter '$' no reconocido
TITULO ;         // P001: Se esperaba CADENA, se encontró PUNTOCOMA

6. Interfaz de Usuario y Despliegue

Se ha desarrollado una Single Page Application (SPA) utilizando Flask para el backend y Vanilla JavaScript para el frontend.

  • Editor: Implementación de un `textarea` optimizado para código.
  • API REST: El servidor recibe código en crudo y retorna un JSON con el HTML, la Tabla de Símbolos y los Errores.
  • Preview Dinámico: Uso de `srcdoc` en iFrames para evitar recargas de página.
