¿Qué es el Lenguaje WebLang?

WebLang es un lenguaje de marcado semántico y simplificado diseñado para construir interfaces web modernas y adaptables a gran velocidad. Está pensado para eliminar la sintaxis ruidosa y repetitiva del HTML5 tradicional (como el cierre manual de etiquetas, llaves angulares y ruido visual), reemplazándola por una sintaxis elegante y estructurada basada en bloques y directivas claras.

A diferencia de otros lenguajes de marcado empíricos, la compilación de WebLang está estrictamente guiada por la **Teoría de Autómatas Formales**:

⚡

Escaneo Léxico (FA)

Junta caracteres letra a letra en unidades lógicas llamadas tokens. Utiliza una matriz de transición que procesa la entrada en tiempo lineal $O(N)$ de forma 100% determinista.

⚙️

Análisis de Pila (PDA)

Un autómata con memoria de pila ($\Gamma$) vigila el anidamiento jerárquico. Garantiza que cada etiqueta abierta se cierre en el orden exacto, previniendo páginas rotas.

🎨

Salida Multipresentación

Genera HTML5 semántico combinando componentes de UI avanzados y layouts responsivos con 5 temas estéticos listos para producción.

¿Cómo funciona la compilación en Nebula Studio?

Para entender cómo funciona el compilador de WebLang, imaginemos que es una línea de ensamblaje en dos fases principales:

Fase 1: El Analizador Léxico (LexerFA) — "El Lector de Letras"

Su tarea es ir leyendo tu código carácter por carácter de izquierda a derecha. No comprende la estructura, solo clasifica palabras y caracteres individuales en "cajas" etiquetadas llamadas Tokens.

  • Si lee la palabra TITULO, la guarda en un token de tipo COMANDO.
  • Si lee texto rodeado de comillas como "Hola", crea un token de tipo CADENA conteniendo Hola.
  • Si encuentra símbolos de control como ; o {, genera tokens de tipo PUNTOCOMA o LLAVE_A.
  • Error Léxico (L001): Si lee un carácter prohibido (como $ o @) o una comilla sin cerrar, el lector se detiene e informa de inmediato.

Fase 2: El Analizador Sintáctico (ParserPDA) — "El Organizador de Bloques"

Recibe la lista de tokens generados por el Lexer y verifica que sigan un orden gramatical válido. Para asegurar la jerarquía, utiliza una **Pila (Stack)**, que funciona exactamente como una pila de platos:

  • Cuando se abre un contenedor como CONTENEDOR {, el Parser pone el plato de div en la pila (**PUSH**).
  • Si adentro encuentra TITULO "Hola";, abre un tag <h1>, introduce el texto y genera el cierre </h1> de inmediato debido al punto y coma ;.
  • Cuando encuentra una llave de cierre }, saca el plato superior de la pila (**POP**), que en este caso es el div, y genera el tag de cierre </div> correspondiente.
  • Error Sintáctico (P001) / Anidamiento (S001): Si colocas un token inesperado (por ejemplo, omitir un punto y coma ;) o intentas escribir un comando sin abrir primero su contenedor obligatorio (como un ELEMENTO fuera de una LISTA), el autómata de pila no encontrará el plato correcto en el tope y lanzará un error detallado.

Especificación Formal y Gráficos de Autómatas

El compilador de WebLang opera bajo el rigor científico de la teoría de la computación. Todo el procesamiento de código se divide en dos motores basados en autómatas formales estrictamente guiados por matrices:

Diagrama de Transición de Estados (FA Léxico)

Inspección de Estado

🖱️

Haz clic en cualquier nodo o estado del autómata léxico para analizar su comportamiento, alfabeto y transiciones.

* Los estados con doble círculo son estados finales de Aceptación (Aceptan Token).

Definición Formal del Autómata Finito Léxico (FA)

El LexerFA es un autómata finito determinista (DFA) que realiza el escaneo de caracteres. Matemáticamente se define como una 5-tupla ML = (Q, Σ, δ, q0, F):

  • Q (Estados): {Q0, Q1, Q2, Q3, Q4, Q5, Q7, Q8, Q9, Qerror}
  • Σ (Alfabeto): Letras, Dígitos, Comillas ", Punto y coma ;, Llaves { }, Barra diagonal /, Espacios y Saltos de línea.
  • q0 (Estado Inicial): Q0 (Inicio de lexema).
  • F (Estados Finales de Aceptación): {Q1, Q3, Q7, Q8, Q9} (al transitar al estado especial -2, se emite el token correspondiente al último estado válido y se mantiene el carácter leído para el siguiente token).
Diagrama de Transición de Estados (PDA Sintáctico de Pila)

Inspección de Estado

💾

Haz clic en cualquier nodo o estado del autómata sintáctico para analizar su comportamiento, manipulación de la pila ($\Gamma$) y acciones asociadas.

* El estado Q99 (EOF) es el estado de aceptación formal donde la pila se vacía por completo hasta el símbolo base (#).

Definición Formal del Autómata con Pila (PDA)

El ParserPDA es un autómata de pila no determinista formalizado mediante un mapeo directo en matriz, encargado de evaluar el anidamiento y la sintaxis. Se define matemáticamente como una 7-tupla MP = (Q, Σ, Γ, δ, q0, Z0, F):

  • Q (Estados): {Q0, Q1, Q2, Q3, Q4, Q5, Q99}
  • Σ (Alfabeto de Entrada): {COMANDO, CADENA, PUNTOCOMA, LLAVE\_A, LLAVE\_C, EOF}
  • Γ (Alfabeto de la Pila): {h1, h2, p, ul, li, div, section, a, table, tr, td, &dots;, #}
  • q0 (Estado Inicial): Q0
  • Z0 (Símbolo inicial de la pila): #
  • F (Estados Finales / Aceptación): {Q99} (se alcanza en el token EOF si la pila contiene únicamente el símbolo inicial #).

Reglas de Anidamiento y Jerarquía

Al igual que en un autómata formal, existen restricciones sobre qué símbolos pueden estar arriba de otros en la pila. La siguiente guía especifica la estructura y jerarquía de contención obligatoria para escribir código sin fallos sintácticos:

Restricciones del Autómata (Uso de Pila)

Elementos de Lista

El comando ELEMENTO sólo puede invocarse si en el tope de la pila está ul (es decir, dentro de un bloque LISTA { ... }) o li (para reemplazo implícito).

Sublistas Anidadas

El comando SUBLISTA sólo puede declararse dentro de un ELEMENTO (es decir, cuando li está en el tope de la pila).

Celdas de Tabla

El comando FILA exige estar dentro de table, y CELDA exige estar directamente dentro de una tr (FILA { ... }).

Estructura de Árbol HTML5 Sugerida 

Raíz
 ├── NAVEGACION
 ├── HERO
 ├── CONTENEDOR
 │    ├── GRID
 │    │    ├── COLUMNA
 │    │    └── COLUMNA
 │    ├── TABLA
 │    │    └── FILA
 │    │         └── CELDA
 │    ├── FORMULARIO
 │    │    ├── ENTRADA
 │    │    └── BOTON
 │    └── CONSULTA
 │         └── DATO
 └── PIE
Nota: Los delimitadores { } actúan abriendo y cerrando los tags contenedores, mientras que ; cierra las instrucciones lineales que no llevan bloques.

Catálogo de Errores y Diagnóstico

La pila de errores de Nebula clasifica minuciosamente cada anomalía en cuatro códigos distintos, lo que te permite comprender y corregir el marcado inmediatamente:

L001

Error Léxico (Lexema Inválido)

Módulo: Lexer Determinista

Ocurre cuando el escáner se topa con un carácter ilegal que no pertenece al alfabeto del lenguaje (como $, @, %), o cuando inicias una cadena de texto con comillas " pero el renglón finaliza antes de cerrarla.

❌ Incorrecto (Falla) 
PARRAFO "Bienvenidos al manual @ Nebula ;
✨ Correcto (Compila) 
PARRAFO "Bienvenidos al manual Nebula" ;
C001

Comando No Válido (Palabra Clave Desconocida)

Módulo: Diccionario de Gramática

Ocurre cuando el compilador procesa un lexema que tiene toda la estructura sintáctica de un comando (en mayúsculas y sin comillas), pero su palabra clave no está registrada en el vocabulario oficial.

❌ Incorrecto (Falla) 
IMPRIMIR "Hola Mundo" ;
✨ Correcto (Compila) 
PARRAFO "Hola Mundo" ;
P001

Error Sintáctico (Token Inesperado)

Módulo: Autómatas Sintácticos

Se genera al romper la secuencia de transición esperada. Por ejemplo, al omitir el delimitador punto y coma ; al finalizar una directiva lineal, o escribir dos cadenas de texto continuas sin el comando correspondiente.

❌ Incorrecto (Falla) 
TITULO "Bienvenidos" /* Falta el ; */
PARRAFO "Este texto fallará" ;
✨ Correcto (Compila) 
TITULO "Bienvenidos" ;
PARRAFO "Este texto funcionará perfectamente." ;
S001

Error de Anidamiento (Estructura de Pila)

Módulo: Integridad de Pila

Es un error semántico/estructural jerárquico. Ocurre cuando invocas un comando hijo que requiere un elemento padre obligatorio en la pila sintáctica, pero el parser detecta que se declaró fuera del contenedor correspondiente.

❌ Incorrecto (Falla) 
ELEMENTO "Este elemento flota libremente" ;
✨ Correcto (Compila) 
LISTA {
    ELEMENTO "Ahora sí está dentro de LISTA" ;
}

Ejemplo de Código Completo y Complejo

A continuación puedes observar una plantilla estructurada y variada en WebLang de alta fidelidad. Puedes hacer clic en copiar y pegarla directamente en el Nebula Editor para compilarla y jugar con los 5 temas de previsualización: 

// ==================================================
// EJEMPLO MAESTRO: WebLang Studio Showcase
// ==================================================

NAVEGACION {
    TITULO "Nebula Space OS";
    ENLACE "https://google.com" "Explorar Docs";
    ENLACE "/docs" "Manual Técnico";
}

HERO {
    ENCABEZADO "El Futuro del Marcado Web";
    PARRAFO "Diseñado para transpilar pseudocódigo a HTML5 semántico utilizando teoría matemática de autómatas.";
    BOTON "Iniciar Proyecto";
}

CONTENEDOR {
    ENCABEZADO "Características de WebLang";
    
    GRID {
        SECCION {
            ENCABEZADO "Autómatas de Pila";
            PARRAFO "Validación estricta del orden jerárquico de las etiquetas mediante transiciones algebraicas en una pila.";
        }
        
        SECCION {
            ENCABEZADO "Sintaxis Limpia";
            PARRAFO "Olvídate de las etiquetas ruidosas. Escribe comandos claros con bloques bien delimitados.";
        }
        
        SECCION {
            ENCABEZADO "Alto Rendimiento";
            PARRAFO "El análisis de tokens funciona mediante matrices en O(N) sin estructuras IF complejas.";
        }
    }

    DIVISOR;

    ARTICULO {
        ENCABEZADO "Estilos de Texto Admitidos";
        PARRAFO "WebLang admite una rica gama de formatos en línea:";
        
        LISTA {
            ELEMENTO { NEGRILLA "Texto en Negrita para ideas fuertes."; }
            ELEMENTO { CURSIVA "Texto en Cursiva para comentarios."; }
            ELEMENTO { SUBRAYADO "Texto Subrayado de importancia."; }
            ELEMENTO { PEQUENO "Notas pequeñas de pie de página."; }
            ELEMENTO { CODIGO "print('Hello WebLang!');"; }
        }
    }

    DIVISOR;

    CONSULTA {
        ENCABEZADO "Dashboard de Compilación";
        DATO "Tokenizador Estado" "Activo";
        DATO "Parser de Pila" "Sin Errores";
        PROGRESO "100" "100";
    }
}

PIE {
    PARRAFO "© 2026 WebLang Studio - Compilación formal y diseño premium.";
}
