1. Introducción al Sistema

El traductor **MiniWebLang** representa la culminación de los principios de diseño de compiladores aplicados a la web moderna. No es solo un convertidor de etiquetas; es un motor de análisis basado en **teoría pura de autómatas**.

A diferencia de los parsers convencionales cargados de condicionales (if/else), nuestro sistema utiliza un enfoque **"Data-Driven"** donde la lógica reside en matrices de adyacencia y tablas de despacho. Esto garantiza una complejidad temporal de **O(n)** y una escalabilidad sin precedentes.

2. Modelo Matemático Formal

El sistema se modela matemáticamente como un Autómata de Pila (PDA) de 7 tuplas:

M = (Q, Σ, Γ, δ, q₀, Z₀, F)

  • Q (Estados): {Q0, Q1, Q2, Q3, Q4, Q5, Q_ERR, Q_FIN}
  • Σ (Alfabeto): {COMANDO, CADENA, NUMERO, LLAVE_A, LLAVE_C, PUNTOCOMA, EOF}
  • Γ (Pila): {h1, h2, p, ul, li, section, a, img, #}
  • q₀: Q0
  • Z₀: # (Símbolo de fondo)
  • F: {Q_FIN}

Función de Transición δ:

δ(q, σ, γ) → (q', γ') define que estando en el estado *q*, leyendo el token *σ* y teniendo *γ* en el tope de la pila, transicionamos al estado *q'* y reemplazamos *γ* por *γ'*.

4. Lógica del Autómata de Pila (PDA)

El Parser no solo valida el orden, sino que gestiona la **Semántica de Contexto**. Por ejemplo, el comando `ELEMENTO` realiza una verificación del tope de la pila para confirmar que se encuentra dentro de una `LISTA`.

Algoritmo de Acción de Comandos

parser_stack.pyPython Logic
def _action_command(self, token):
    cmd = token.value
    rules = self.CMD_RULES.get(cmd)
    
    # 1. Validación de Contexto (Tope de Pila)
    if rules.get('require_top') and self.stack[-1] != rules['require_top']:
        self.error_pile.push("S001", "Error de Contexto")

    # 2. Generación de Apertura de Etiqueta
    self.html.open_tag(rules['tag'])
    
    # 3. Empuje a la Pila para rastrear anidamiento
    if rules.get('push'):
        self.stack.append(rules['push'])
    
    return rules['next']

5. Arquitectura de Componentes Internos

5.1 Tabla de Símbolos de Alto Rendimiento

5.2 Generador de HTML Abstracto

El componente `HTMLGenerator` mantiene un buffer de strings optimizado. No escribe a disco hasta que el PDA alcanza el estado de aceptación `Q_FIN` (99).

6. Gestión de Errores y Categorización

El sistema divide los fallos en 4 niveles críticos:

NIVEL 1
Léxico (LXXX): Errores en la formación de palabras. Recuperación inmediata saltando el caracter inválido.
NIVEL 2
Sintáctico (PXXX): Orden de tokens inválido. El PDA entra en Panic Mode buscando el próximo `;`.
NIVEL 3
Semántico (SXXX): Lógica de anidamiento incorrecta. Se registra pero se intenta continuar la traducción.
NIVEL 4
Comando (CXXX): Comando no reconocido en el diccionario de gramática actual.

7. Guía de Extensibilidad

Para agregar un nuevo comando al lenguaje (ejemplo: `HEADER`), siga estos pasos:

  1. Agregue `HEADER` al `COMMAND_MAP` en `grammar.py`.
  2. Defina su comportamiento en la matriz `CMD_RULES` de `parser_stack.py`: 
    { 'HEADER': {'tag': 'header', 'push': 'header', 'next': 1} }
  3. Reinicie el servidor Flask.

9. Manual de Usuario y FAQ

¿Cómo instalo el proyecto?

Clona el repo y ejecuta `pip install -r requirements.txt`. Luego corre `python app.py`.

¿Por qué mi código no compila?

Verifica que cada instrucción termine en `;`. El punto y coma es el delimitador de sincronización del PDA.
